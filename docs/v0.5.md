# VPS Linux 0.5 and vpsctl 0.5.0 candidate

v0.4 was published on 2026-10-28 from `b5bc3c5301226211dfb2c457a477c3eed8f75876`
(see the publication record in [v0.4.md](v0.4.md)). This cycle changes the image
policy and the utility, so the stable label moves to `0.5`; published releases
remain unchanged.

## Changes in this cycle

Image policy (first boot):

- sysctl hardening drop-in: kernel information disclosure restrictions
  (`dmesg_restrict`, `kptr_restrict`), unprivileged BPF disabled, setuid core
  dumps off, `fs.protected_*` link protections pinned, ICMP redirects and
  source-routed traffic refused.
- Core dumps fully disabled: journald stores none and systemd starts every
  process with `RLIMIT_CORE=0`.
- SSH brute-force/idle limits: `LoginGraceTime 20`, `MaxAuthTries 3`,
  `ClientAliveInterval 300` × `ClientAliveCountMax 3`, `RequiredRSASize 3072`.
- Weekly `fstrim.timer` enabled; `nftables` package added (no rules shipped).
- Static motd hint pointing to vpsctl.

Build system and utility:

- vpsctl 0.5.0: generated man page (`vpsctl(1)`) and bash/zsh completions are
  shipped in the Debian package; payload validation covers the new files.
- `cargo-deny` policy (advisories, licenses, bans, sources) runs in CI.
- Keyless GitHub artifact attestations sign every published bundle artifact.
- Dependabot for GitHub Actions and Cargo; community files
  (SECURITY.md, CONTRIBUTING.md, issue/PR templates, CODEOWNERS).
- `SOURCE_DATE_EPOCH` is exported by `build.sh`; reproducibility status is
  tracked in [reproducibility.md](reproducibility.md).

## Testing

Existing image acceptance plus `tests/verify-guest.sh` extensions assert the
effective sysctl values, disabled core dumps, `fstrim.timer`, the motd script
and the extended SSH policy on the booted guest. `tests/test_configuration.py`
adds static policy tests.

The owner executed the full offline two-instance suite and the online
`--release-check` (NTP, Docker Hub, HTTP, reboot) against the
`e9b701acbe29` build of this content on 2026-10-29; see
[validation.md](validation.md). Publication requires a fresh fully tested main
run with `publish_release`, exactly as for previous stable versions.

## Build and release

From a clean committed checkout, after installing tools from building.md:

```sh
./vpsctl/scripts/package-deb.sh
python3 scripts/vpsctl_package.py --source . --json
sudo ./build.sh --check
sudo ./build.sh
./tests/smoke-test.sh output/<printed-build-id>/vps-linux-v0.5.qcow2 --release-check
```

Or dispatch **Validate image build system** on `main` with
build_and_boot/online_tests enabled; `publish_release` creates the stable
`v0.5` tag and release after every test passes. Existing release tags/assets
are unchanged.
